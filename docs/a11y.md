# Accessibility (a11y) policy

Every app scaffolded from this template ships with an automated a11y gate
and a documented manual AAA pass.

## Automated (blocking, runs in `pnpm run check`)

- `e2e/a11y.spec.ts` runs axe (via `@axe-core/playwright`) against every
  public route: `/`, `/contact`, `/feedback`, `/help`.
- Enforced tags: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`,
  plus `best-practice`. Any violation fails the build.
- Unit-level axe: `vitest-axe` in component tests (see
  `src/app/page.test.tsx`).
- Radix UI primitives in `src/components/ui` provide keyboard navigation,
  focus management, and ARIA by default — hand-rolled equivalents are
  banned by AGENTS.md.

## Manual AAA pass (required before release)

axe has no AAA rules, so AAA is a human checklist on top of the automated
gate. Run through it for every new route:

- Contrast ≥ 7:1 for body text, ≥ 4.5:1 for large text and UI components.
- No information conveyed by color alone (icons + text labels).
- Focus visible at all times; skip-link present.
- All functionality usable with keyboard only, no timing limits.
- Flashing content absent; animations reducible via `prefers-reduced-motion`.
- Target size ≥ 44×44 CSS px for interactive elements.
- Language declared (`<html lang>`); landmarks and heading levels in order.
- Forms: every control labelled, errors announced via `role="status"` /
  `aria-live`.

## Local commands

- `pnpm test:a11y` — run just the axe route audit.
- `pnpm run check` — full gate incl. a11y (e2e includes `a11y.spec.ts`).
